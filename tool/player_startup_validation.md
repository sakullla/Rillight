# Windows player startup validation

Use Flutter 3.47.6 and the verified Windows core SDK. The normal Flutter
renderer remains enabled, including Impeller. Windows warms one hidden player
engine after the logged-in main window renders and after a player exits. It
does not attach credentials, open a decoder, or request media while idle.
Playback adopts that engine; closing/logging out retires it. A failed prewarm
falls back to a normal process launch. Other desktop platforms retain cold
launches and share the concurrent metadata preparation.

Build the ordinary `lib/main.dart` release target before benchmarking:

```powershell
$env:RILLIGHT_CORE_PREFIX_WINDOWS_X64 = "$PWD/build/local-current-windows-sdk"
flutter build windows --release
python tool/player_startup_bench.py --executable build/windows/x64/runner/Release/rillight.exe --out build/player-validation/startup-cold --runs 3
python tool/player_startup_bench.py --executable build/windows/x64/runner/Release/rillight.exe --prepared --warm --out build/player-validation/startup-warm --runs 3
python tool/player_startup_bench.py --executable build/windows/x64/runner/Release/rillight.exe --prepared --warm --metadata-delay-ms 1000 --out build/player-validation/startup-delayed --runs 3
```

Output directories must be new. The fixture media must already exist under
`build/player-validation/media` (generated by `tool/player_smoke.ps1`). Requires
an interactive Windows desktop and Pillow. The harness uses synthetic
credentials, isolated settings/cache and a loopback Emby fixture. It captures
the real window's central test-pattern panels and checks changing pixels.
It rejects ordinary desktop/poster colors as first-frame evidence.

`visibleMs` measures an HWND becoming visible. `coloredFrameMs` measures the
first screen sample matching the synthetic video. `changingFrameMs` confirms
later pixel changes; sampling intervals mean this is not frame-accurate
instrumentation. Warm measurements start at the play/start signal, after the
hidden engine is ready; `prewarmMs` separately records background startup.
`--prepared` reproduces the production host's concurrent metadata handoff.
The benchmark does not drive the detail-page tap, measure physical audio or
establish remote-server throughput. Metadata delay affects Item/User APIs,
not video bandwidth or packet loss.

## Startup regression coverage

Cover cold and prewarmed child startup, concurrent metadata handoff, stale session
callbacks, account switching and shutdown cleanup. Opening HLS resources whose
expiry retries are exhausted must be eligible for renewal before a first frame.

For transport, check bounded read-ahead on sequential small ranges, immediate
delivery of a gated first body fragment, disk-budget changes, late cache setup,
stable native input identities and interrupted seeks. Synthetic request counts
and completion conditions are separate from real-server throughput.

Store baseline/candidate timings, binary hashes and observations in ignored
evidence directories. Rebuild the normal application entrypoint after smoke tests.
