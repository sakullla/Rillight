# 增强处理第二轮性能优化

> 历史记录：2026-10-09 已按用户要求移除全部画质增强，包括超分、Anime4K、补帧、降噪和锐化。本文增强实现与测试路径不再代表当前功能；最终状态见 [全项目优化报告](global_optimization.md)。

2026-10-09。本轮基线为 `8447a14`，此前已完成合并 `origin/main` 和第一轮优化，见 [前轮记录](dolby_enhancement_optimization.md)。

## 实现

### SDR 单独锐化

仅 RGBA8、无插帧/降噪/Anime4K/超分的有效组合走新路径：直接从带 stride 的字节输入计算三行整数横向和，输出锐化 RGBA。避免整帧 RGB/alpha 浮点解码、浮点输出及重编码；除最终输出外，锐化临时存储由整帧降为三行 RGB 整数和，即 O(width)。

透明度逐字节保留，边界仍按复制边缘处理。整数域与原归一化浮点域可能在舍入临界点相差一个 8-bit 量化级；回归明确接受最多 1 的 RGB 差异。HDR 和混合增强继续使用原浮点路径，不能据此宣称它们获得同等加速。

### Anime4K CPU 解释执行

每个 pass 开始时绑定纹理，将每个 term 的采样坐标分别按 x/y 预计算。内层像素循环不再重复字符串 map 查找和归一化坐标除法。保留原浮点运算顺序、双线性采样、矩阵累加顺序和固定着色器资产。

RunChain 的本地 MAIN 平面使用移动语义进出 map，去掉两次整帧复制。中间平面的生命周期没有重新设计；失败只影响 ApplyAnime4k 的本地工作副本。

新增差分回归保留 `8447a14` 的标量 pass/chain 作为独立慢速对照：覆盖单行/单列、偏移、缩放、正负 ReLU、bias、shuffle、缺失纹理，以及四条实际固定 shader chain。MinGW 和 MSVC 下均逐浮点值相等。

## 测量

同一 Windows 主机，MinGW GCC `-std=c++17 -O3`，没有 `fast-math`。构建与 Flutter 测试结束后进行交替测试，每轮交换先后顺序。计时包括处理所需分配；模型资产加载不计入 Anime4K 热路径。

| 测试 | 基线 ms/帧 | 本轮 ms/帧 | 耗时下降 |
| --- | ---: | ---: | ---: |
| 1920×1080 RGBA、35% 锐化 | 75.478 | 12.058 | 84.02% |
| 3840×2160 RGBA、35% 锐化 | 306.357 | 49.535 | 83.83% |
| Anime4K light，320×180 → 640×360，restore + upscale | 815.020 | 450.597 | 44.71% |

锐化每轮预热 3 帧，测量 15 帧取中位数，5 轮再取中位数。Anime4K 每轮预热 1 帧，测量 5 帧，3 轮再取中位数。

| 测试 | 基线各轮中位数 | 候选各轮中位数 |
| --- | --- | --- |
| 1080p 锐化 | 74.961, 74.934, 75.984, 76.591, 75.478 | 11.881, 12.490, 12.058, 11.892, 12.072 |
| 4K 锐化 | 302.648, 306.357, 315.745, 306.167, 311.917 | 48.840, 50.001, 49.008, 49.535, 50.177 |
| Anime4K | 811.762, 815.020, 818.380 | 451.182, 446.161, 450.597 |

锐化基线使用 `git show 8447a14:packages/rillight_player/native/core/video_enhancer.cpp`，与候选使用同一版测试驱动。`video_enhancer_test.cpp --benchmark` / `--benchmark-4k` 可复测；Anime4K 测试程序用 `--reference` / `--candidate`，并提供 shader 目录或构建时的 `RILLIGHT_ANIME4K_DIR`。

原始记录：`build/perf-round2/bench-results.json`、`bench.log`。这些是合成输入的 CPU 算法对比，不是实际播放器 FPS、端到端延迟、GPU/功耗或物理设备验收。Anime4K 即使优化后，在此 320×180 输入上仍需约 451ms，不能称为 CPU 实时处理。

## 验证

- Windows 原生核心增量构建成功，CTest **13/13** 通过（包含新增 Anime4K 对照测试）。
- 锐化回归覆盖所有 1～100 强度、随机像素、padded stride、边界及透明度、与插帧组合；原 HDR 暗值、时间线及参数校验继续通过。
- MSVC `/W4 /WX /O2` 下两个增强测试均编译并运行通过。首次独立运行 Anime4K 测试缺少 shader 路径；补上真实资产路径后通过，未放宽断言。
- Android NDK 28.2 的 arm64-v8a、armeabi-v7a、x86_64 对两份修改的增强源码均通过 `-Wall -Wextra -Werror -fsyntax-only`。这不是 APK 链接或设备运行证据。
- 本轮 Dart 改动的验证见 [窗口研究](window_layout_research.md)。前轮完整 Flutter 测试为 1574 通过、2 跳过；本轮执行相关模块回归，没有重跑整个测试集。
- 本轮首次首页批次误传了不存在的 `window_chrome_cases.dart` 路径，该批次报告失败；修正实际测试路径后 74 项通过，另窗口/外壳 38 项通过。

未更换模型、改动 HDR 色彩算法或引入额外工作线程。本轮没有 Linux/macOS 构建、实际视频/物理音频、HDR 显示和硬件稳定性新证据。
